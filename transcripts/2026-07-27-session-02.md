## Where the agent got something wrong (and was caught)

**Bug.** First run of the privacy e2e suite failed with HTTP 500 on every authenticated POST. Server logs:

```
PrismaClientKnownRequestError:
Invalid `this.prisma.collection.create()` invocation in
.../collections.repository.ts:48

Foreign key constraint violated: `foreign key`
```

**Root cause.** `UsersService.ensureExists` was only called from `/me`. The privacy tests bypassed `/me` and POSTed directly to `/collections`, so the User FK target didn't exist yet. The lazy-upsert promise in `UsersService` ("every authenticated request goes through `ensureExists`") was a lie — there was no path enforcing it for resource writes.

**Fix.** Added `EnsureUserGuard` (`@nestjs/common` `CanActivate`) that runs after `JwtAuthGuard` and calls `ensureExists` for every authed request. Wired it onto `CollectionsController` and `BookmarksController`. Imported `UsersModule` into both resource modules so the guard can resolve `UsersService`.

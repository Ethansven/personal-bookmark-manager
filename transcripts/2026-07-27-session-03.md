## Decisions

- **ADR-004:** React Router 7.18.1 (latest stable; brief said ≥v8 but no v8 released).
- **Frontend PKCE client:** `oidc-client-ts` per ADR-003.
- **MUI v9 quirks** — `ListItem button` → `ListItemButton`; `verbatimModuleSyntax` is on by default in the Vite scaffold.
- **No `/all` page, no full-text search, no Dockerfile, no CI** — all §3.4 bonuses, deferred per the brief's instruction to focus on §3.1–§3.3 first.

## Where the agent got something wrong

- **Duplicate import.** First cut of `pages/Bookmarks.tsx` had `import { Bookmark, Bookmark, ... }` — left over from a paste mistake. Caught by TS.
- **Wrong MUI v9 API.** Used `<ListItem button>` which was removed in MUI v9. Caught by TS error TS2769.
- **Wrong export name.** Imported `UserManagerSettings` from oidc-client-ts. It's not exported; switched to `ConstructorParameters<typeof UserManager>[0]`. Caught by TS error TS2353.
- **Wrong `verbatimModuleSyntax` style.** Mixed type and value imports in the same statement; needed `import type { ... }` for the interfaces. Caught by TS error TS1484.
- **Misread the docs.** Tried to set `code_challenge_method: 'S256'` on `UserManagerSettings`. oidc-client-ts computes PKCE automatically based on `response_type: 'code'` and uses S256 unconditionally. Documented in code comment.

All five were TS errors caught on first compile. No runtime bugs.
